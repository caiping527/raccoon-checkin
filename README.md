# 小浣熊签到（raccoon-checkin）

> 商汤小浣熊 每日登录延效。云端 GitHub Actions 自动跑，本机不用开机、不用开客户端。

**仓库名说明**：GitHub 不支持中文仓库名（会被静默丢弃），所以仓库名是英文
`raccoon-checkin`。这个仓库就是**小浣熊签到**，中文别名记在仓库描述里。

---

## 这个仓库是干什么的

商汤小浣熊每天登录可以拿 300 积分，但**积分单笔只活 7 天**，而且
「登录一次延长 7 天」是个误解：只有当天那一笔会顺延，更早的各笔到期时间不变。

所以必须**每天登录一次**，才能让每笔 300 积分各自活满 7 天。

这个仓库就是替你每天自动登录，不用你手动开客户端。

| 项目 | 说明 |
|---|---|
| 平台 | 商汤小浣熊（Raccoon） |
| 每日收益 | 300 积分 |
| 积分有效期 | 7 天（每笔独立计算） |
| 最大可持有 | 300 × 7 = 2100 |
| 运行方式 | GitHub Actions 每天自动，约北京 01:00 |
| 本机要求 | 无。不用开机、不用开客户端 |

---

## 重要说明

- **仓库必须保持私有**。签到类仓库一旦公开，仓库名和 workflow 会进搜索引擎，
  平台侧排查时容易顺藤摸瓜，被扫号只是时间问题。
- **令牌不进代码**。所有凭据都在 `Settings → Secrets and variables → Actions`，
  代码里只写 `${{ secrets.XXX }}`。
- **日志已脱敏**。令牌只打印前缀或长度，完整值不落日志。
- 本仓库是自动化脚本，请勿 fork 到公开仓库 —— fork 出来如果默认公开，
  等于把账号密码摊在网上。

## 运行时间

| 北京时刻 | 动作 |
|---|---|
| 约 01:00 | 云端自动登录全部账号，逐个延长积分有效期 |
| 签到后 | 推送各账号积分余额与过期日播报（仅失败才推企业微信） |

GitHub 的定时任务会随机延迟（高峰期可达 5~6 小时），所以实际执行时间
通常在 01:00 ~ 07:00 之间，属正常。

---

## 多账号怎么跑

账号清单只在 AI路由魔改版（`data\accounts\raccoon\credentials.json`），
本目录不保存任何账号密码；脚本按 AI路由 里的清单逐个登录、逐个上报。

云端按矩阵（matrix）展开，一个账号一个 job，互不影响。
某个账号失败不会中断其它账号。

---

## 失败会怎样

- 签到失败 → 推企业微信（只推失败，成功不打扰）
- 连续多天没跑 → 心跳告警会点名到本仓库
- 令牌过期 → 提示回 AiRoute / 账号管理重新登录

## 心跳监测

本仓库已被纳入「自动心跳监测」，Healthchecks 里的名字是 `签到-小浣熊`。

判定口径：

| 状态 | 含义 |
|---|---|
| `up` | 正常，今天已上报 |
| `grace` | 还没到今天的上报点，宽限期内，**不是故障** |
| `down` | 真的没跑，去 Actions 看当天 run 并补签 |

## 排错

| 现象 | 原因 | 怎么办 |
|---|---|---|
| Actions 红叉 | 账号或密码错 | 回本机「小浣熊签到 → 账号管理」改密码 |
| 提示 need captcha | 触发风控 | 停一天再试，或换网络环境手动登录一次 |
| 心跳 down | 当天没跑 | Actions 页面点 Run workflow 补签 |
| 积分没涨 | 当天已登录过 | 正常，同一笔不会重复发 |

## 安全

- 账号密码只存 GitHub Secrets（加密），不进代码、不进日志
- 仓库私有，不出现在公开搜索结果
- 需要停用：删除对应 Secret，或在 Actions 页面 Disable workflow
