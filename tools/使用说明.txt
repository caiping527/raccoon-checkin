==================================================
 商汤小浣熊 · 云端每日登录延效 · 一键更新工具
==================================================

【这套系统做什么】
  小浣熊每天 00:00 自动发 300 积分，但当天没有「登录动作」的话，
  这笔积分当日 24:00 就清零；当天登录过，有效期延长到 7 天。
  云端 GitHub Actions 每天北京时间 09:17 替每个账号打一次登录动作，
  并核对积分账本确认延效成功。全程不开电脑、不用打开客户端、不用点任何按钮。

【怎么用：双击就行，不用选账号】
  1. 打开商汤小浣熊客户端，登录你要登记 / 续期的那个账号
  2. 双击「一键更新.bat」
  3. 工具自动读出当前登录账号的尾号，并自动完成：
       · 建立账号专属 Environment「acct-<尾号>」
       · 把登录令牌写进这个环境的 Secret（与别的账号完全隔离）
       · 把尾号追加到云端账号列表（重复运行不会重复添加）
       · 触发一次云端只读自检
  4. 看到【成功】即可关闭窗口

【想加第 2 个、第 3 个账号？直接跑，不用改任何代码】
  客户端退出当前账号 → 登录新账号 → 再双击一次「一键更新.bat」。
  账号数量没有上限，每个账号一个独立 job，一个失败不影响其他账号。
  云端账号列表存在仓库变量 RACCOON_ACCOUNTS 里（只存尾号，不含任何凭据）。

【什么时候需要再跑一次】
  · 收到企业微信「⚠️ 令牌临期」提醒（令牌剩余 7 天时提前提醒）
  · 收到「❌ 签到失败」且原因是令牌过期
  小浣熊登录令牌实测有效期 30 天，所以大约每月登录一次、双击一次即可。
  各账号令牌独立，到期时间可能不同，按提醒里的尾号逐个处理。

【三个令牌别搞混】
  · GH_TOKEN（本机环境变量）：GitHub 令牌，只用于本机工具写 Secret / 触发工作流。
    你现有的通用长期令牌可用；更安全的做法是新建一枚只授权本仓库
    Secrets 读写 + Actions 写的细粒度令牌。
  · GH_PAT（云端 Secret）：同一类 GitHub 令牌，供云端在 refresh_token 轮换后
    自动把新值写回 Environment Secret。不配置也能跑，只是轮换后需手动更新。
  · RACCOON_ACCESS_TOKEN（账号专属 Secret）：小浣熊登录令牌，本工具的更新对象，
    约 30 天过期。绝不显示、不落盘、不进命令行参数。

【企业微信推送】
  沿用你现有配置，二选一或都填（仓库级 Secret）：
    WECOM_APP      = corpid,corpsecret,touser,agentid    （企业微信自建应用）
    WECOM_WEBHOOK  = 群机器人完整 webhook 或仅 key
  默认「成功不打扰」，只有签到失败、令牌剩余 ≤7 天时推送，消息带账号尾号。
  想每次成功都推：把仓库变量 SUCCESS_NOTIFY 设为 1。

【常见失败与处理】
  · 未找到登录态文件 → 打开客户端并完成登录；或检查是否已登录过
  · 登录令牌已过期 → 客户端退出并重新登录该账号后重试
  · 账号校验不通过 → 确认登录的是目标账号（工具零选择，自动识别）
  · gh 执行失败 → 检查 GH_TOKEN、网络、仓库是否存在且当前账号有管理员权限
  · 自检触发失败 → 令牌已写入，不影响第二天定时；可到 Actions 页手动 Run workflow

【确认更新历史】
  同目录「更新记录.txt」每次运行追加一行：时间 / 尾号 / 写入位置 / 结果，
  不含任何令牌内容。

【安全边界】
  · 令牌只从本机写入 GitHub Secrets，不上传任何第三方
  · 仓库建议设为 Private；公开仓库 60 天无活动会被 GitHub 停用定时任务
  · 云端与桌面客户端共享同一会话：客户端刷新登录态可能让云端令牌失效，
    出现 401 时重新双击本工具即可
  · 请仅用于自己的账号，并遵守平台服务条款
