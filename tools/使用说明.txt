【这套系统做什么】
  小浣熊没有「签到」按钮，桌面客户端一启动就会打一次登录接口，
  当天的 300 积分随之入账。云端 GitHub Actions 每天北京时间 09:17
  替每个账号打一次同样的动作，并查积分账本确认「今天已入账」。
  不开电脑、不用打开客户端、不用点任何按钮。

  关于 300 积分会不会过期：以你在客户端的实测为准，本工具不下结论。
  账本里确实有 expire_at 字段（本次显示 7 天后），但全账号没有任何
  「过期扣减」记录，且这号 11-09 当天才注册，没有跨天数据可判断。
  所以程序只认「今天的 300 有没有到账」，不拿 expire_at 档位判成败，
  也就不会因为这个问题误报失败、误发企微提醒。
  想自己确认：看每天运行摘要里的 balance.daily_points，
  逐日涨（300→600→900）就是不过期；每天回到 300 就是会失效。

【账号尾号 4060 和 7080 是怎么回事】
  两个都对，只是标识体系不一样：
    · 4060 = 你手机号尾号（客户端界面上看到的）
    · 7080 = 登录令牌里的内部用户ID尾号（sub 字段，令牌里没有手机号）
  本目录「账号标签.txt」把两者对起来，写法：内部ID尾号=手机号尾号
    7080=4060
  于是云端环境名、企微提醒、日志都显示你认得的 4060；
  内部ID尾号 7080 单独存进该环境的 Secret，用来防止换号时串号。
  换号后若表里没登记，工具会自动用内部ID尾号显示并提示你补一行，
  ——不补也能正常跑，双击照样零操作。

【怎么用：双击就行，不用选账号】
  1. 打开商汤小浣熊客户端，登录你要登记 / 续期的那个账号
  2. 双击「一键更新.bat」
  3. 工具自动完成：
       · 读出当前登录态，识别账号（不显示令牌）
       · 建立账号专属 Environment「acct-4060」
       · 写入 RACCOON_ACCESS_TOKEN（登录令牌）
         + RACCOON_ACCOUNT_ID（内部ID尾号，防串号）
       · 把 4060 追加到云端账号列表（重复运行不会重复添加）
       · 触发一次云端只读自检
  4. 看到【成功】即可关闭窗口

【换账号 / 加第 2 个、第 3 个账号】
  客户端退出当前账号 → 登录新账号 → 再双击一次「一键更新.bat」。
  是的，就这么简单，不用改任何代码、不用上网页加东西。
  新号会被「追加」进去，原来的号继续照常签到，不会互相覆盖。
  每个账号一个独立 Environment、一个独立 job，一个失败不影响其他账号。
  想让新号也显示手机号尾号：双击后工具会打印它的内部ID尾号，
  在「账号标签.txt」照格式补一行，再双击一次即可。

【云端签到会打断我正在跑的任务吗】
  不会。云端只发三个只读请求（setting_info / bills / balance），
  不写会话状态、不轮换令牌。本机登录态里没有 refresh_token，
  所以刷新令牌的接口根本不会被调用。
  实测：11-09 12:48 云端完整签到后，客户端 14:12 仍正常显示、积分可见。
  真正要注意的是反方向：客户端退出或重新登录，可能让云端那张旧令牌
  失效（云端报 401）。遇到时重新双击本工具即可，不影响客户端任务。

【什么时候需要再跑一次】
  · 收到企业微信「⚠️ 令牌临期」提醒（令牌剩余 7 天时提前提醒）
  · 收到「❌ 签到失败」且原因是令牌过期 / 401
  小浣熊登录令牌实测有效期 30 天，大约每月登录一次、双击一次即可。
  各账号令牌独立，到期时间可能不同，按提醒里的尾号逐个处理。

【三个令牌别搞混】
  · GH_TOKEN（本机环境变量）：GitHub 令牌，只用于本机工具写 Secret / 触发工作流。
    你现有的通用长期令牌可用；更安全的做法是新建一枚只授权本仓库
    Secrets 读写 + Actions 写的细粒度令牌。
  · GH_PAT（云端 Secret）：同类 GitHub 令牌，供云端在 refresh_token 轮换后
    自动把新值写回 Environment Secret。不配置也能跑。
  · RACCOON_ACCESS_TOKEN（账号专属 Secret）：小浣熊登录令牌，本工具的更新对象，
    约 30 天过期。绝不显示、不落盘、不进命令行参数。

【企业微信推送】
  沿用你现有配置，二选一或都填（仓库级 Secret）：
    WECOM_APP      = corpid,corpsecret,touser,agentid    （企业微信自建应用）
    WECOM_WEBHOOK  = 群机器人完整 webhook 或仅 key
  默认「成功不打扰」，只有签到失败、令牌剩余 ≤7 天时推送，消息带账号尾号。
  想每次成功都推：把仓库变量 SUCCESS_NOTIFY 设为 1。

【常见失败与处理】
  · 未找到登录态文件 → 打开客户端并完成登录
  · 登录令牌已过期   → 客户端退出并重新登录该账号后重试
  · 凭据归属不符     → 该环境的令牌属于另一个号，重新登录正确账号后双击
  · gh 执行失败      → 检查 GH_TOKEN、网络、仓库是否存在且有管理员权限
  · 自检触发失败     → 令牌已写入，不影响第二天定时；可到 Actions 页手动 Run

【确认更新历史】
  同目录「更新记录.txt」每次运行追加一行：时间 / 尾号 / 写入位置 / 结果，
  不含任何令牌内容。云端每次运行的积分分项可在 Actions 的 Step Summary 查看。

【安全边界】
  · 令牌只从本机写入 GitHub Secrets，不上传任何第三方
  · 仓库保持 Private；公开仓库 60 天无活动会被 GitHub 停用定时任务
  · 请仅用于自己的账号，并遵守平台服务条款
