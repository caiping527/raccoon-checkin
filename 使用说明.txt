【这套系统做什么】
  小浣熊没有「签到」按钮，桌面客户端一启动就会打一次登录接口，
  当天的 300 积分随之入账。云端 GitHub Actions 每天北京时间 09:17
  替每个账号打一次同样的动作，并查积分账本确认「今天已入账」。
  不开电脑、不用打开客户端、不用点任何按钮。

  关于 300 积分会不会过期：以你在客户端的实测为准，本工具不下结论。
  账本里确实有 expire_at 字段（本次显示 7 天后），但全账号没有任何
  「过期扣减」记录。所以程序只认「今天的 300 有没有到账」，
  不拿 expire_at 档位判成败。想自己确认：看每天 Actions 运行摘要里的
  balance.daily_points，逐日涨（300→600→900）就是不过期。

【★ 为什么之前切三个号会收到 401 失败提醒】
  已实测确认：小浣熊服务端按登录会话(sid)鉴权。在客户端点
  「退出登录」或重新登录，会让该账号之前的令牌立刻失效，
  云端再用旧令牌就报 HTTP 401 authorization_verify_error。
  换请求头、调 refresh 接口都救不回来（实测全部 401）。

  更麻烦的是一个死循环：
    · 客户端把登录态存在本机 auth.json 里，关掉软件再打开
      会自动恢复成原来那个号（比如 7100），不会停在登录页
    · 想登新号，只能点「退出登录」—— 而这一下正好会撤销会话
  所以「关软件 → 重开 → 登新号」这条路走不通，
  「退出 A → 登录 B → 双击登记」又会让 A 的云端签到坏掉。
  三个号依次切完，往往只有最后登录的那个还活着。

  ★ 正解：不要在客户端登录任何一个号。
    用「密码登录.bat」拿手机号 + 密码直接向官方换一张独立令牌，
    整个过程不碰客户端，桌面端切号 / 退出登录都影响不到云端。

【★ 推荐：密码登录.bat（每个账号做一次）】
  1. 双击「密码登录.bat」
  2. 按提示输入该账号的手机号（11 位）和密码
     ★ 密码默认「明文显示」，方便肉眼核对有没有输错；
       想隐藏可命令行加 --hide-password。
     密码不落盘、不写日志、不进命令行参数（只在本机内存里）。
  3. 窗口会问一句：是否把密码也存到云端？（直接回车 = 选 Y）
       Y = 默认 ★ 云端每天自动用密码重新登录，取全新独立会话。
           一劳永逸：不用管 30 天令牌过期，也不用再跑本工具，
           桌面客户端爱登哪个号、爱怎么切都不影响签到。
           代价：账号密码会加密存放在 GitHub 该账号专属
           Environment Secret 里（GitHub Secrets 是加密存储）。
       N = 只把本次换到的令牌存进云端，密码不存。
           约 30 天后令牌到期，收到企微提醒时再跑一次即可。
     想跳过询问：命令行加 --store-password 或 --no-store-password。
  4. 看到【成功】即可关闭窗口。三个账号就依次跑三次，
     每次输对应账号的手机号和密码，工具自动分开存放、互不干扰。
  5. 工具会自动触发一次云端只读自检，去 Actions 看是否全绿。

  技术说明（不用管）：官网同款 AES-128-CFB 加密，
  接口 POST /api/iam/v1/auth/login/password/phone，
  实现在 scripts/iam_login.py，纯标准库、零第三方依赖。

【备用：一键更新.bat（依赖客户端登录态）】
  只在「当前客户端正好登录着要登记的那个号」时使用：
  双击后工具读取本机 auth.json 里的令牌登记到云端。
  换号会触发上面的 401 问题，多账号场景不建议用。
  「安全换号.bat」可保存/替换本机登录态实现免登出切换，
  但首次仍需在客户端登录一次，不如密码登录干净。

【账号尾号：手机号 4060 / 内部ID 7080】
  客户端显示的是手机号尾号 4060；登录令牌里的 7080 是内部用户ID，
  两者不是一回事，也都不是错。
  工具会查小浣熊只读账号接口拿到掩码手机号（134****4060），
  自动取尾 4 位当账号标签：
    · 云端环境名 acct-4060、账号列表、日志、企业微信推送
      一律显示「手机号尾号4060」
    · 内部ID尾号只存进云端 Secret 做防串号校验，推送里绝不出现
    · 「账号标签.txt」由工具自动维护，平时不用打开、不用手改

【企业微信推送】
  默认「成功不打扰」，只有签到失败、令牌剩余 ≤7 天时才推。
  消息里的账号固定写成「手机号尾号4060」，不会推内部ID标签。
  沿用你现有配置（仓库级 Secret）：
    WECOM_APP      = corpid,corpsecret,touser,agentid
    WECOM_WEBHOOK  = 群机器人完整 webhook 或仅 key
  想每次成功都推：把仓库变量 SUCCESS_NOTIFY 设为 1。

【云端签到会打断我正在跑的任务吗】
  不会。云端只发只读请求（setting_info / bills / balance），
  不写会话状态、不会把桌面端挤下线。
  若开启了云端密码登录(Y)，每次运行会为该账号新取一张令牌，
  属于同一账号的新会话；如果桌面端正开着同一个号，
  有可能被服务端视为新设备登录，这点请在首次验证时留意。

【常见失败与处理】
  · 双击 bat 一闪而过 → 本版本已修复（bat 统一为纯 ASCII + CRLF，
    中文提示由 Python 输出，末尾保留 pause）。若仍出现，右键 bat
    →「以管理员身份运行」或在该目录打开 cmd 手动敲 bat 名看报错
  · 提示「密码登录失败：HTTP 200 OK」→ 老版本解析 bug，已修复。
    官网后端返回 {code:"OK", data:{access_token,...}}，token 在 data 层。
    注意：密码错会返回 401 AUTH_ACCOUNT_OR_PASSWORD_INVALID，
    所以看到 200 OK 就代表密码是对的，不是输错。
  · 密码想隐藏不显示 → 命令行运行 python password_login.py --hide-password
  · 密码登录失败 / 提示账号或密码不正确 → 先去官网登录页手工登一次
    确认密码，再重跑；若提示人机验证或尝试次数过多，等一会儿再试
  · 未找到登录态文件（一键更新.bat） → 打开客户端并完成登录
  · 登录会话已撤销(401) → 又在客户端点了退出登录；
    双击「密码登录.bat」重新登记该账号即可
  · 凭据归属不符 → 该环境的令牌属于另一个号，重新登记正确账号
  · 缺少 GH_TOKEN → 把 GitHub 令牌设为系统环境变量
  · gh 执行失败   → 检查 GH_TOKEN、网络、仓库权限
  · 自检触发失败  → 令牌已写入，不影响定时；可到 Actions 手动 Run

【三个令牌别搞混】
  · GH_TOKEN（本机环境变量）：GitHub 令牌，用于本机工具写 Secret。
    你现有的通用长期令牌可用；更安全的做法是新建一枚只授权本仓库
    Secrets 读写 + Actions 写的细粒度令牌。
  · GH_PAT（云端 Secret）：同类令牌，供 refresh_token 轮换后回写。
    不配置也能跑。
  · RACCOON_ACCESS_TOKEN（账号专属 Secret）：小浣熊登录令牌，
    约 30 天过期；开启云端密码登录后会被每天自动刷新。
    绝不显示、不进命令行参数。

【安全边界】
  · 密码只在本机内存出现，传给 gh 一律走 stdin，不落盘、不打印
  · 选 Y 时密码存 GitHub 加密 Secret，不进代码、不进日志、不进推送
  · 令牌只从本机写入 GitHub Secrets，不上传任何第三方
  · 手机号只取掩码号码后 4 位用于显示（选 Y 时需存完整号码用于登录）
  · 仓库保持 Private；公开仓库 60 天无活动会被 GitHub 停用定时任务
  · 请仅用于自己的账号，并遵守平台服务条款
  · 若曾在聊天/截图里明文发过账号密码，建议去官网改一次密码，
    再重跑「密码登录.bat」即可
