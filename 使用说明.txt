【日常：什么都不用做】
  GitHub Actions 每天北京时间 09:17 自动为三个账号
  （手机号尾号 4060 / 7100 / 6717）各模拟一次桌面端登录动作，
  当天 300 积分随之入账。不开电脑、不打开客户端、不用点任何按钮。
  账号密码已存在各自专属的加密 Secret 里，云端每天现取新会话，
  所以客户端切号、退出登录、30 天令牌到期都不会影响签到。

  签到成功默认不推企业微信（不打扰）；但检测到「积分快过期」时
  会推一条「今日优先用号」榜单，详见下方章节。
  想确认有没有跑：打开 https://github.com/caiping527/raccoon-checkin/actions
  看是否全绿。想每次成功都收到推送：把仓库变量 SUCCESS_NOTIFY 设为 1。

    2. 该账号改了密码

【积分构成（云端实测 2026-11-09）】
  你在客户端看到的「积分」是 available_points（总可用积分）：
    4060 = 10300 分（签到 300 + 奖励 10000）
    7100 =  5535 分（签到   0 + 奖励  5535）
    6717 =  3899 分（签到 300 + 奖励  3599）
  早期榜单只显示 daily_points，所以看起来只有 300 甚至 0，
  口径确实小了，现已改成显示总可用积分并拆开两类。

  到期日有两个来源：
    1) expire_at 字段：每日签到发的 300，约 6 天后到期
       （11/09 发的 → 11/15 23:59 到期）
    2) event_name 文本：部分奖励把日期写在发放说明里，
       例如「奖励积分（2027-10-19 到期）」，这类还有近一年
  其余奖励入账（新人礼包、邀请奖励、体验补偿等）未标注到期日，
  程序单独列出，不猜测过期时间。

  ★ 结论：短期内真正会过期的是「每日签到 300」这一档，
    每号最多滚动 6~7 天约 2000 分；那几千奖励分大多长期有效。
    所以「物尽其用」能省下的是每天新发的 300，不是全部余额。

【积分过期检测 + 今日优先用号】
  账本只记发放流水、不记逐笔消耗，单看发放日会误报：
  例：7100 账本有 7 笔 300 分在 11/09~11/15 到期，
  可当时签到类余额 daily_points=0 —— 早就花光了，不该再提醒去用。
  因此程序会用「当前余额」按最早到期先扣（FIFO），
  且签到类 / 奖励类各自用对应余额分别摊回各批次，
  算出真正「快过期且还没花掉」的分数。

  每天签到后会额外做两件事：
    1. Actions 摘要列出每个号的积分过期分布与未用余额
    2. 三个号按「临期未用积分」从多到少排序，
       有临期积分时推一条企业微信，告诉你今天优先用哪个号跑代码；
       多个号都临期时，整张榜单一起发，积分多的排前面

  ★ 系统只负责「检测 + 排序提醒」，不会自动替你消耗积分：
    看到推送后，用榜首那个号登录小浣熊去跑代码即可。
    用掉之后余额下降，次日自动就不再提醒这个号。

  可调的仓库变量（不设也能用）：
    RACCOON_EXPIRE_WARN_DAYS  临期阈值，默认 2 天
    RECOMMEND_NOTIFY          always=每天推全榜 / 0=关闭 /
                              未设=只有临期积分时才推（默认）

【成功判据不变】
  判成功只看一件事：**今天的积分账本里有没有新入账 300**
  （按 daily_grant 的 created_at 严格比对今天）。
  过期检测是附加的观测功能，不参与成功/失败判定，
  所以无论积分是否过期，都不会误报签到失败。

  ★ 不建议改成「每 7 天登一次」或「每 7 天轮一个号」：
    · 积分按账号独立，别的号登了不会给这个号加分
    · 少登一天就少一天的新 300，可花的积分反而变少
    · 云端每天跑只是几次只读请求，零成本、不开电脑、
      不打断桌面端正在跑的任务
    · 判据要求「今天入账」，降频会导致没登的那天被判失败并推告警

【常见失败】
  · 401 会话已撤销 → 该账号没登记过密码登录，或密码改了；
    双击「密码登录.bat」重跑该账号即可
  · HTTP 400 iam_confirm_required → 新版已自动处理（云端登录后
    先 POST /api/web/auth/v1/iam/confirm 确认会话），无需人工干预
  · 网络超时 / HTTP 5xx → 云端到小浣熊偶发抖动，已自动重试 2 次；
    仍失败时企微会写明「云端网络波动」，不影响下次定时
  · bat 一闪而过 → 已修复（纯 ASCII + CRLF + pause）；
    若仍出现，在该目录打开 cmd 手动敲 bat 名看报错
  · 提示「密码登录失败：HTTP 200 OK」→ 旧版解析 bug，已修复。
    密码错会返回 401，所以 200 OK 代表密码是对的
  · 缺少 GH_TOKEN → 把 GitHub 令牌设为系统环境变量
  · 凭据归属不符 → 该环境的令牌属于另一个号，重新登记正确账号

【安全边界】
  · 密码只在本机内存出现，传给 gh 一律走 stdin，不落盘、不打印
  · 选 Y 后密码存 GitHub 加密 Secret，不进代码、不进日志、不进推送
  · 仓库保持 Private；公开仓库 60 天无活动会被 GitHub 停用定时任务
  · 请仅用于自己的账号，并遵守平台服务条款
  · 若曾在聊天/截图里明文发过密码，建议去官网改一次密码，
    再对那个账号重跑一次「密码登录.bat」
