【说明的层级】
  整套框架的最终形态与设计理念，见 工具箱\说明.html
  （工具箱「一键部署 → 总说明」直接打开，冲突时以它为准）。
  本文件只讲小浣熊签到这一件事。

【框架边界】
  · 工具箱\ 是框架核心，只放公用凭据；本模块私有的东西放本目录。
  · 小浣熊账号密码是本模块私有数据，存在本目录 账号.json，
    不进 工具箱\配置.json，也不进一键换机流程。
  · 删掉其它任一模块文件夹，不影响本模块运行。
  · 一键换机只部署本机 AiRoute，不动云端；本模块的账号与云端 Secret
    由「账号管理」和「批量登记」自己管，换机对它们没有影响。

【日常：什么都不用做】
  GitHub Actions 每天 UTC 16:58（北京时间次日 00:58）自动为配置里的每个
  账号各模拟一次桌面端登录动作，当天 300 积分随之入账。不开电脑、不打开
  客户端、不用点任何按钮。GitHub 调度高峰可能延迟数小时，属正常现象。
  账号密码已存在 GitHub 加密 Secret 里，云端每天现取
  新会话，所以客户端切号、退出登录、令牌到期都不会影响签到。
  签到完成后每天必推一条企业微信「每日积分播报」：逐个账号列出当前积分、
  积分哪天开始过期、该提前哪天用掉；签到成功本身不额外打扰，
  失败 / 令牌临期才单独告警，详见下方章节。
  想确认有没有跑：https://github.com/caiping527/raccoon-checkin/actions
  想每次成功都收到推送：把仓库变量 SUCCESS_NOTIFY 设为 1。
  不想收每日播报：把仓库变量 RECOMMEND_NOTIFY 设为 0。

【入口 / 唯一需要动手的时候】
  加账号、改密码：路由工具箱.exe →【小浣熊签到】→ 账号管理
  把账号登记到云端：路由工具箱.exe →【小浣熊签到】→ 小浣熊签到
                    或双击本目录「批量登记.bat」
  只有两种情况要跑「小浣熊签到」：1. 新增一个账号  2. 该账号改了密码。

【怎么加账号：账号框 + 密码框，分开填，不用逗号】
  1. 工具箱【小浣熊签到 → 账号管理】打开编辑窗口：
     · 上面一个「账号」框、一个「密码」框，各填各的，不用逗号、不用每行一个
     · 点「保存」，这一组就明文列进下方的大方框
     · 大方框里点中某一条、点「删除选中」即可删掉，随时可增删改
     · 明文只存本机 账号.json，本机自用方便核对
  2. 双击「批量登记.bat」——脚本依次登录、依次写 GitHub，
     窗口逐账号打印结果，最后触发一次云端自检

  ★ 不用开客户端、不用切号、不用一个账号跑一次、不用手拼「手机号,密码」。
    小浣熊是商汤的独立账号体系，AiRoute 里没有它的凭据，做不到「直接读取」；
    但它本来也不需要切客户端：用手机号 + 密码调登录接口换独立令牌即可。
  ★ 默认把密码也存进云端加密 Secret，云端每天自动登录，
    连令牌过期都不用再管。已登记过的账号重复跑也无害。

【写到哪】
  每个账号一个 Environment「acct-<尾号>」，里面写：
    RACCOON_ACCESS_TOKEN / RACCOON_ACCOUNT_ID
    RACCOON_PHONE / RACCOON_PASSWORD（默认存）
  并把尾号登记进仓库变量 RACCOON_ACCOUNTS，重复运行不会重复添加。

【配置改哪里】
  公用凭据在 工具箱\配置.json，用工具箱「一键部署 → 公用配置」明文编辑：
    · github_token     往 GitHub 写数据用的 PAT
    · raccoon_repo     目标仓库
  改完点「保存并应用」，下次运行全部生效；只改本机、不动云端。
  账号密码不在这里，在【小浣熊签到 → 账号管理】。
  「保存并应用」只写本机环境变量和心跳凭据，不会把任何数据推到 GitHub；
  真正写云端的是「批量登记.bat」。

  ★ 统一配置里只有一套 GitHub owner / PAT；这里的「多账号」指多个
    小浣熊业务账号映射到同一 owner 的仓库与 Environment。

【积分构成（云端实测 2026-11-09）】
  客户端显示的「积分」是 available_points（总可用积分）：
    4060 = 10300 分（签到 300 + 奖励 10000）
    7100 =  5535 分（签到   0 + 奖励  5535）
    6717 =  3899 分（签到 300 + 奖励  3599）
  早期榜单只显示 daily_points，看起来只有 300 甚至 0，口径偏小；
  现已改成显示总可用积分并拆开两类。

  到期日有两个来源：
    1) expire_at 字段：每日签到发的 300，约 6 天后到期
    2) event_name 文本：部分奖励把日期写在发放说明里，这类还有近一年
  其余奖励入账未标注到期日，程序单独列出，不猜测过期时间。
  ★ 短期内真正会过期的是「每日签到 300」这一档，
    每号最多滚动 6~7 天约 2000 分；那几千奖励分大多长期有效。

【积分过期检测 + 每日积分播报】
  账本只记发放流水、不记逐笔消耗，单看发放日会误报（余额早就花光了）。
  因此程序用「当前余额」按最早到期先扣（FIFO），且签到类 / 奖励类
  各自用对应余额分别摊回各批次，算出真正「快过期且还没花掉」的分数。
  每天签到完成后固定做三件事：
    1. Actions 摘要列出每个号的当前积分与积分过期分布（Markdown 榜单）
    2. 企业微信推送一条「每日积分播报」：每个号一行，写明
       当前积分（签到分 / 奖励分）、积分开始过期的日子、
       以及「提前一天用掉」的具体日期；今明两天就到期会直接提示今天用掉
    3. 按「临期未用积分」从多到少排序，给出今天优先用哪个号跑代码
  登记 N 个账号却只收到 M 份数据时，播报会明确写出缺数据；
  签到失败的号显示「未取到」而不是假的 0 分，不会漏号没人发现。
  ★ 系统只负责「检测 + 排序提醒」，不会自动替你消耗积分：
    看到推送后，用榜首那个号登录小浣熊去跑代码即可。
  可调的仓库变量（不设也能用）：
    RACCOON_EXPIRE_WARN_DAYS  临期阈值，默认 2 天
    RECOMMEND_NOTIFY          0=关闭每日播报 / 未设或其它值=每天推（默认）
    SUCCESS_NOTIFY            1=每次签到成功也单独推一条（默认不推）

【成功判据】
  只看一件事：今天的积分账本里有没有新入账 300
  （按 daily_grant 的 created_at 严格比对今天）。
  过期检测是附加的观测功能，不参与成功/失败判定，不会误报签到失败。

【常见失败】
  · 401 会话已撤销 → 该账号没登记过或改了密码 → 账号管理里改好，重跑批量登记
  · HTTP 400 iam_confirm_required → 云端已自动处理，无需人工干预
  · 网络超时 / HTTP 5xx → 云端自动重试 2 次；仍失败时企微会写明
    「云端网络波动」，不影响下次定时
  · 「本模块还没有小浣熊账号」→ 到【小浣熊签到 → 账号管理】加一组
  · 缺少 GitHub 令牌 → 工具箱「公用配置」重填 github_token
  · bat 一闪而过 → 在该目录打开 cmd 手动敲 bat 名看报错
  · 凭据归属不符 → 该环境的令牌属于另一个号，重跑批量登记正确账号

【命令行（一般用不到）】
  python batch_login.py --dry-run              只预览账号清单，零写入
  python batch_login.py --no-check             登记但不触发云端自检
  python batch_login.py --no-store-password    不把密码存进云端

【目录说明】
  账号.json          ← 本模块私有账号清单（账号 / 密码分字段，明文，可删）
  account_editor.py  ← 账号管理窗口（工具箱「账号管理」动态加载）
  批量登记.bat       ← 登记到云端（工具箱「小浣熊签到」即调用它）
  batch_login.py     ← 主程序：读 账号.json + 公用配置 → 依次登录 → 依次写 GitHub
  password_login.py  ← 旧版「单个账号手输」入口，兼容保留，日常不用
  密码登录.bat       ← 同上
  update.py          ← 被复用的公共库（尾号识别、gh 调用等）
  scripts\           ← 云端签到脚本，本机不用管
    iam_login.py        官网同款 AES-128-CFB 密码登录
    raccoon_checkin.py  签到主逻辑
    wecom_notify.py     企业微信推送：单账号告警 + 每日积分播报 + 跨账号临期排序
    summarize_result.py Actions 运行摘要（含积分过期分布）
  使用说明.txt       ← 本文件

【安全边界】
  · 账号密码只从本模块 账号.json 读取，本机明文；传给 gh 一律走 stdin，
    不进命令行、不打印、不落运行日志
  · 云端密码存 GitHub 加密 Secret，不进代码、不进日志、不进推送
  · GitHub Secret 只写不读：官网拿不回明文密码，改密码要在账号管理里重填
  · 仓库保持 Private；公开仓库 60 天无活动会被 GitHub 停用定时任务
  · 请仅用于自己的账号，并遵守平台服务条款
