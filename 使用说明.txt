【这套系统做什么】
  小浣熊没有「签到」按钮，桌面客户端一启动就会打一次登录接口，
  当天的 300 积分随之入账。云端 GitHub Actions 每天北京时间 09:17
  替每个账号打一次同样的动作，并查积分账本确认「今天已入账」。
  不开电脑、不用打开客户端、不用点任何按钮。

  关于 300 积分会不会过期：以你在客户端的实测为准，本工具不下结论。
  账本里确实有 expire_at 字段（本次显示 7 天后），但全账号没有任何
  「过期扣减」记录，且这号 11-09 当天才注册，没有跨天数据可判断。
  所以程序只认「今天的 300 有没有到账」，不拿 expire_at 档位判成败。
  想自己确认：看每天 Actions 运行摘要里的 balance.daily_points，
  逐日涨（300→600→900）就是不过期；每天回到 300 就是会失效。

【账号尾号：手机号 4060 / 内部ID 7080】
  客户端显示的是手机号尾号 4060；登录令牌里那个 7080 是内部用户ID，
  两者不是一回事，也都不是错。

  工具会自己查小浣熊的只读账号接口，拿到掩码手机号（134****4060），
  自动取尾 4 位当账号标签。于是：
    · 云端环境名 acct-4060、账号列表、日志、企业微信推送
      一律显示「手机号尾号4060」
    · 内部ID尾号只存进云端 Secret 做防串号校验，推送里绝不出现
    · 本目录「账号标签.txt」由工具自动写，平时不用打开、不用手改

【★ 重要：多账号换号必须用「安全换号.bat」】
  原因（已实测确认）：小浣熊服务端按登录会话(sid)鉴权，
  在客户端点「退出登录」或重新登录，会让该账号之前的令牌立刻失效，
  云端再用旧令牌就报 HTTP 401 authorization_verify_error。
  换平台请求头、调 refresh 接口都救不回来（实测全部 401）。
  所以「退出 A → 登录 B → 双击」这种换号方式，会让 A 的云端签到坏掉。
  三个号依次切完，往往只有最后登录的那个还活着。

  正确做法：把每个账号的登录态存到本机，以后换号只替换文件，
  全程不触发登录 / 登出接口，云端令牌就不会被撤销。

  首次配置（每个账号做一次）：
    1. 客户端登录账号 A
    2. 双击「一键更新.bat」→ 把 A 的令牌登记到云端
    3. 双击「安全换号.bat」→ 选 [1] 保存当前登录态
    4. 完全关闭客户端（直接关窗口 / 任务管理器结束，
       不要点「退出登录」，先保存好正在跑的任务）
    5. 重新打开客户端 → 登录账号 B
    6. 回到第 2 步，为 B 重复一次

  以后换号（再也不用登录）：
    双击「安全换号.bat」→ 选 [2] → 输入手机号尾号 →
    按提示关闭客户端并回车 → 重新打开客户端就是那个账号。
    不需要登录、不需要退出登录、不需要再跑「一键更新.bat」。

  本机「账号凭据\」目录保存的是明文登录令牌，已加入 .gitignore，
  不会上传、不要外传。令牌有效期约 30 天，到期时按企微提醒
  重新登录一次并双击「一键更新.bat」即可。

【怎么用「一键更新.bat」】
  1. 打开商汤小浣熊客户端，登录你要登记 / 续期的那个账号
  2. 双击「一键更新.bat」
  3. 工具自动完成：
       · 只读查询账号接口，识别手机号尾号（不显示令牌、不显示完整号码）
       · 建立账号专属 Environment「acct-4060」
       · 写入 RACCOON_ACCESS_TOKEN（登录令牌）
         + RACCOON_ACCOUNT_ID（内部ID尾号，仅防串号）
       · 把 4060 追加到云端账号列表（重复运行不会重复添加）
       · 触发一次云端只读自检
  4. 看到【成功】即可关闭窗口

  只有当账号接口临时不可用、且本机也没缓存过这个号时，
  窗口才会问一句「请输入该账号手机号后 4 位」，输一次即可。
  也可以直接跑：一键更新.bat --label 1234

【企业微信推送】
  默认「成功不打扰」，只有签到失败、令牌剩余 ≤7 天时才推。
  消息里的账号固定写成「手机号尾号4060」，不会推内部ID标签。
  沿用你现有配置，二选一或都填（仓库级 Secret）：
    WECOM_APP      = corpid,corpsecret,touser,agentid    （企业微信自建应用）
    WECOM_WEBHOOK  = 群机器人完整 webhook 或仅 key
  想每次成功都推：把仓库变量 SUCCESS_NOTIFY 设为 1。

【云端签到会打断我正在跑的任务吗】
  不会。云端只发三个只读请求（setting_info / bills / balance），
  不写会话状态、不轮换令牌。本机登录态里没有 refresh_token，
  刷新令牌的接口不会被调用；本机工具查账号信息也是纯只读。
  反方向要注意：客户端「退出登录 / 重新登录」会让云端旧令牌失效，
  这也是上面必须用「安全换号.bat」的原因。

【什么时候需要再跑「一键更新.bat」】
  · 收到企业微信「⚠️ 令牌临期」提醒（令牌剩余 7 天时提前提醒）
  · 收到「登录会话已被服务端撤销(401)」提醒 → 说明又在客户端
    点了退出登录，按上面「安全换号」流程重新登记该账号
  小浣熊登录令牌实测有效期 30 天，大约每月处理一次。
  各账号令牌独立，到期时间可能不同，按提醒里的手机号尾号逐个处理。

【三个令牌别搞混】
  · GH_TOKEN（本机环境变量）：GitHub 令牌，用于本机工具写 Secret / 触发工作流。
    你现有的通用长期令牌可用；更安全的做法是新建一枚只授权本仓库
    Secrets 读写 + Actions 写的细粒度令牌。
  · GH_PAT（云端 Secret）：同类 GitHub 令牌，供云端在 refresh_token 轮换后
    自动把新值写回 Environment Secret。不配置也能跑。
  · RACCOON_ACCESS_TOKEN（账号专属 Secret）：小浣熊登录令牌，本工具的更新对象，
    约 30 天过期。绝不显示、不进命令行参数。

【常见失败与处理】
  · 未找到登录态文件 → 打开客户端并完成登录
  · 登录令牌已过期   → 登录该账号后双击「一键更新.bat」
  · 登录会话已撤销(401) → 客户端点过退出登录；按「安全换号」流程重登
  · 凭据归属不符     → 该环境的令牌属于另一个号，重新登记正确账号
  · 无法取得手机号   → 按窗口提示输 4 位尾号，或用 --label 参数
  · gh 执行失败      → 检查 GH_TOKEN、网络、仓库是否存在且有管理员权限
  · 自检触发失败     → 令牌已写入，不影响第二天定时；可到 Actions 页手动 Run

【确认更新历史】
  本目录「更新记录.txt」每次运行追加一行：时间 / 手机号尾号 /
  写入位置 / 结果，不含任何令牌内容。云端每次运行的积分分项
  可在 Actions 的 Step Summary 查看。

【安全边界】
  · 令牌只从本机写入 GitHub Secrets，不上传任何第三方
  · 手机号只取接口返回的掩码号码后 4 位，不保存完整号码
  · 仓库保持 Private；公开仓库 60 天无活动会被 GitHub 停用定时任务
  · 请仅用于自己的账号，并遵守平台服务条款
